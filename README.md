# 次どこ行く？ こうきのやること

旅行Instagram「次どこ行く？」[@tsugi_doko47](https://www.instagram.com/tsugi_doko47/) の運用で、**こうきがやる作業だけ**を1画面にまとめたWebアプリです。
Googleスプレッドシート「運用管理シート」を直接読み書きします。iPhoneのホーム画面に追加して使えます（PWA）。

- 構成：Next.js 15（App Router）＋ Google Sheets API v4（サービスアカウント）、Vercel にデプロイ
- 日付・時刻の判定はすべて日本時間。投稿時刻は毎回 20:00
- 開くときにパスコードを入れる（Cookieで180日間ログインしたまま）

## 画面

1. **確認して予約する**：ステータス＝承認待ち。Canvaで開く／キャプションをコピー／Business Suite →「予約した」で承認済みに
2. **投稿URLを入れる**：承認済み・投稿済みで、投稿日の20:00を過ぎていて投稿URLが空。保存すると投稿URLを書き、投稿済みに
3. **インサイトを記録する**：投稿済み（またはURLあり）の投稿を、設定タブのルール「インサイト記録」のタイミング（24h・72h・7d）ごとに記録。分析ログの「計測タイミング」列に 24h／72h／7d を書き、同じ投稿日・同じタイミングは二重に記録しない。記録しないまま次のタイミングが来たら、前のものは省略して新しいほうだけ出す
4. **写真の許諾まわり**：メール下書きの送信、DMでの依頼、DMの返事確認、Canvaへの写真アップロード
5. **AIが準備中の投稿**（最大8件）

ヘッダーの下に今のモード（テスト期間中／本番運用）と「切り替え」ボタン、サマリーの下に「今のルール」（設定タブのルール表の今のモードの列）を出します。
切り替えるときは、ルール表の違いを並べて確認してから書き込みます。投稿時刻と「毎週の流れ」の曜日・本数も、ルール表の値を使います。
設定タブが読めない・値が ON/OFF 以外のときは「テスト期間中」として表示し、注意を出します（切り替えはできません）。
6. **毎週の流れ**

## 書き込みのルール

このアプリが書くのは次の3つだけです。ほかのセル・列・タブは変更しません。

| どこ | 何を |
|---|---|
| 投稿カレンダー「ステータス」 | 承認待ち → 承認済み、承認済み → 投稿済み |
| 投稿カレンダー「投稿URL」 | InstagramのURL |
| 分析ログの新しい行 | 投稿日・スポット・投稿形式・7つの数値・記録日・計測タイミング（保存率・エンゲージ率の数式列は触らない） |
| 設定「テスト期間」の行の 値（B2）と 更新日（D2） | ON（テスト期間中）／OFF（本番運用）と切り替えた日。ルール表は変更しない |

- 列は1行目の **見出し名** で探します。見出しが見つからなければエラーを出して書き込みません
- 書く直前にその行を読み直し、投稿日（とステータス）が画面と同じか確かめます。違えば「シートが変わっています」と出して書きません
- インサイトは書く直前に同じ投稿日・同じ計測タイミングがないか再確認します（二重記録しない）。計測タイミングが空の古い行は 72h として扱います
- 通信に失敗しても自動でやり直しません。「最新にする」で確認してからもう一度押してください
- メモ列に「記入例」と入っている行は無視します

## セットアップ

### 1. サービスアカウントを作る（Google Cloud）

1. https://console.cloud.google.com/ を開き、上のプロジェクト選択 →「新しいプロジェクト」（名前は例えば `tsugidoko`）
2. 左メニュー「APIとサービス」→「ライブラリ」→ **Google Sheets API** を検索して「有効にする」
3. 「APIとサービス」→「認証情報」→「認証情報を作成」→「サービスアカウント」
   - 名前は `tsugidoko-app` など。ロールの付与は不要（スキップでOK）
4. できたサービスアカウントを開く →「鍵」タブ →「鍵を追加」→「新しい鍵を作成」→ **JSON** → ダウンロード
   - このJSONは **パスワードと同じ**。人に送らない・Gitに入れない
5. JSON の中の `client_email` と `private_key` を次で使います

### 2. 運用管理シートを共有する

運用管理シートを開き、右上の「共有」→ `client_email` のアドレス（`…@….iam.gserviceaccount.com`）を **編集者** で追加します（通知メールはオフでOK）。

### 3. ローカルで起動する

Node.js 20 以上が必要です。

```bash
npm install
cp .env.example .env.local
```

`.env.local` を開いて値を入れます。

| 変数 | 中身 |
|---|---|
| `SPREADSHEET_ID` | 運用管理シートのID（最初から入っています） |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | JSONの `client_email` |
| `GOOGLE_PRIVATE_KEY` | JSONの `private_key`。`\n` はそのまま、全体を `"` で囲む |
| `APP_PASSCODE` | アプリを開くときのパスコード |
| `AUTH_SECRET` | ランダムな長い文字列（`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` で作れます） |

```bash
npm run dev
```

http://localhost:3000 を開き、パスコードを入れます。

**Googleにつながずに画面だけ試す**：`.env.local` で `SHEETS_MOCK=1` にすると、サンプルデータで動きます（書き込みはメモリ上だけ。本番では使えません）。

テスト：`npm test`（判定ロジックと書き込みルール）

### 4. Vercel にデプロイする

1. このリポジトリを GitHub に push しておく
2. https://vercel.com/new → リポジトリを選んで Import（Framework は Next.js が自動で選ばれます）
3. 「Environment Variables」に `.env.local` と同じ5つを入れる（`SHEETS_MOCK` は入れない）
   - `GOOGLE_PRIVATE_KEY` は `-----BEGIN PRIVATE KEY-----\n…` を `"` なしでそのまま貼ってOK
4. Deploy。できたURLを iPhone の Safari で開く → パスコード → 共有ボタン →「ホーム画面に追加」

パスコードを変えたいとき：Vercel で `APP_PASSCODE` を変えて再デプロイ。今ログインしている端末はすべてログアウトされます。

## うまくいかないとき

| 画面の表示 | どうする |
|---|---|
| 運用管理シートを開く権限がありません | 手順2の共有を確認。Google Sheets API が有効か確認 |
| サービスアカウントの鍵が読み込めません | `GOOGLE_PRIVATE_KEY` の貼り方（`\n`、`"`）を確認 |
| 見出し「〇〇」が見つかりません | シートの1行目の見出し名が変わっていないか確認 |
| シートが変わっています | 「最新にする」を押してからもう一度 |
| 通信が途中で切れました | 書き込めたか分からないので「最新にする」で確認してから |

## 判定の細かいところ

- 「3日以内で未予約」：今日〜3日後（20:00前）が投稿日で、ステータスが承認済み・投稿済み・見送り以外の投稿の数
- 「メールの下書きを送信」：許諾管理のメモに「Gmail下書き作成済み」があり、ステータスがまだ依頼済み・許可・条件付き許可・断られた・返信なしになっていない行
- 連絡先が `@ユーザー名` なら Instagram のURLにしてリンクします。`https://` 以外のリンクは出しません
